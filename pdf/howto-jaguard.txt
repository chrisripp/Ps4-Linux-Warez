                          Optimisation kernel 6.15.4
=======================================================================   
 Pourquoi le kernel 6.x est plus lent sur PS4 ?
=======================================================================
Le kernel 6.x a subi des changements qui pénalisent beaucoup de GPU 
“exotiques” ou anciens, surtout dans les cas suivants :

(1) Le driver AMD (amdgpu) du kernel 6.x n’est pas adapté pour la PS4

La PS4 utilise un GPU Sea Islands / GCN 1.1 (Liverpool).
Ce GPU utilise des parties du driver r600 et amdgpu, 
mais aucune version de Linux ne supporte officiellement ce matériel.
→ Les kernels 5.15.x fonctionnent mieux car ils ont :

-moins de régressions dans le code GCN1.1
-un amdgpu plus léger
-une gestion plus stable du clock, powerplay, fences, etc.
-Le kernel 6.15.4 est peut-être plus “neuf”, 
     mais il est moins optimisé pour ce GPU.  
   
(2) Régressions de performance dans DRM pour les GPU GCN

Depuis Linux 6.0 → 6.8, plusieurs patchs ont modifié :

-IRQ handling
-memory barriers
-power management
-VM scheduler d’amdgpu
Ces changements améliorent RDNA / Vega, 
mais dégradent les vieux GPU GCN
→ notamment la PS4.   

(3) Le kernel 6.x active plus de protections (spectre, meltdown, retpoline, IBPB, IBRS…)

Ces protections :

-coûtent des cycles CPU
-affectent Zen / Intel, mais aussi Jaguar (PS4)
-Sur un petit CPU Jaguar 1.6 GHz, chaque sécurité coûte cher.
Le 5.15.15 en active moins → donc FPS plus élevés.

Heaven score:
5.15.15 = 1200 points
6.15.4 = ~965 points

======================================================================
Sur Jaguar, ça peut donner +20 à +40 % dans certains benchmarks.
======================================================================

Comment compiler en FULL et THIN LTO:

Selon les system linux, utilisé, menuconfig a besoin de pointer sur LLVM,
sinon il ne vous affiche pas les options LTO, vous aurez simplement 
NONE

Pour activer ces fonctions vous devez lancer menuconfig avec cette commande:

make LLVM=1 menuconfig.

Un exemple d'optimisation que j'utilise, pour compiler avec le cpu Jaguars de la ps4:

Pour Jaguard contrairement au 5.x, vous ne pourrez pas le choisir dans les
options de menuconfig. Tout se passe a la compilation en appelant : 
-march=btver2 -mtune=btver2 .

========================================================================
                            LA COMPILAION
========================================================================   

Compiler en Full LTO prends beaucoup de ram, si vous pocéder un :
i3 16G de ram, il y a une chance sur deux, pour que le PC FREEZE.  
Pour palier cela j'ai créer 2 scripts que je vous fournirai et qui,
vous permet de compiler en FULL_LTO avec un i3 16G de RAM.
Pour les experts voic la commande a utiliser pour compiler en 
                      FULL_LTO et THIN_LTO     

make -j$JOBS \
    LLVM=1 \
    KCFLAGS="-march=btver2 -mtune=btver2 -O3 -fomit-frame-pointer -flto -mno-sse4a -mno-xop -mno-tbm -pipe" \
    CC=clang \
    LD=ld.lld \
    AR=llvm-ar \
    NM=llvm-nm \
    STRIP=llvm-strip \
    OBJCOPY=llvm-objcopy \
    OBJDUMP=llvm-objdump \
    READELF=llvm-readelf \
    HOSTCC=clang \
    HOSTCXX=clang++ \
    HOSTAR=llvm-ar \
    HOSTLD=ld.lld                                       
 
 Les scripts lancer: compile-i3-fulllto-v2.sh 
et dans un autre terminal monitor-compilation.sh

Une fois votre bzImage compilé, lancer votre ps4 linux:
Copier/Coller votre bzImage dans /boot
Lancer ce script:  ps4-kernel-complete-analyzer.sh
Pour avoir toutes les informations de votre kernel.                       

Vous pouvez encore optimiser, en recompilant votre mesa pour Jaguard
voici ma ligne de commande actuelle:
    COMPILERFLAGS_OPT = f"-pipe -march=btver2 -mtune=btver2 -O3 -mfpmath=sse -ftree-vectorize -flto -flto={nproc} -g0 -fno-semantic-interposition"
